# AI-помощник для входящих заявок: тема и черновик ответа

Менеджер вводит текст заявки, получает тему и черновик ответа. Решение, что отправить клиенту, остаётся за менеджером.

## Запуск

Нужен Node.js 20 или новее, зависимостей и ключей нет.

```sh
nvm use 24        # или nvm install 20 && nvm use 20; в системе может стоять 18, тогда это обязательный шаг
node server.mjs   # http://127.0.0.1:3000, порт задаётся через PORT
```

## Тесты

```sh
node --test       # или npm test
```

15 тестов на встроенном `node:test`: сбои модели (`[error]`, `[timeout]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`), успешный разбор, невалидный ввод, `parseBody` и `parseModelOutput` напрямую.
Сервер в тестах поднимается на свободном порту `listen(0)` и закрывается в `after` вместе с соединениями, так что `node --test` завершается сам.

## Где проверяется результат AI

`parseModelOutput` в `server.mjs`:

- ответ модели должен быть строкой с JSON (`typeof raw === "string"` → `JSON.parse` в `try/catch`);
- тема — строго `delivery`, `pricing` или `other` (белый список, без нормализации регистра);
- черновик — строка, непустая после `trim`; отдаём обрезанный по краям черновик.

Ожидание модели ограничено 300 мс: `classify(text, { signal: AbortSignal.timeout(300) })` — сигнал передаётся самому имитатору, поэтому отменяется и его задержка.

## Что происходит при сбое

- таймаут, отмена по сигналу, исключение провайдера, не-JSON, чужая тема, пустой черновик → HTTP 200 `{"status":"manual_review","topic":null,"draft":null}`;
- на странице — сообщение менеджеру «Не удалось обработать заявку автоматически…», а предыдущий черновик и тема очищаются;
- пустой, отсутствующий, нестроковый `text`, а также битый JSON и тело больше 64 КБ → HTTP 400 `{"status":"invalid_input"}` и подсказка на странице;
- `mock-ai.mjs` не изменён, поведение имитатора прежнее.

## Польза и метрика

Помощник сокращает время на первый ответ менеджера; метрика — доля заявок, где черновик принят без правок, и среднее время от заявки до ответа клиенту.
